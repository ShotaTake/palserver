# 診断・バックアップ一覧・ワールド復元

3つとも指定の Discord サーバー／チャンネルの Maintainer 専用です。

| コマンド | 内容 |
|---|---|
| `/server diagnose` | SSH、ゲーム応答、保存先へのアクセス、空き容量、記録済みの停止失敗、更新・復元状態を要約 |
| `/server backups` | 新しい順に最大20件のバックアップ名・ファイル更新日時・容量を表示 |
| `/server restore` | 一覧から対象を選び、確認ボタンで復元を要求。成功後はゲームを起動 |

診断・一覧・復元候補の取得では PC を自動起動しません。PC がオフなら起動してから利用してください。SSH 接続失敗は電源オフと断定せず「通信できず状態不明」と表示します。診断は固定項目の確認であり、任意のコマンド実行や生ログの転送は行いません。

## 初回導入

標準構成（ユーザー `valheim` / `palbotctl`、サービス `valheim-server.service`、ワールド `/home/valheim/.config/unity3d/IronGate/Valheim/worlds_local`、バックアップ `/var/lib/gameserver-backups`）向けです。Python 3.11 以上が必要です。独自配置の場合は固定ヘルパーと systemd の書き込み許可先を所有者が調整してください。

変更済みコードを両マシンへ反映してから、プレイヤーがいない時間に実施します。

1. Raspberry Pi で Bot を停止する。

   ```bash
   sudo systemctl stop gameserver-bot.service
   ```

2. サーバー PC のリポジトリで、導入内容を確認してから適用する。

   ```bash
   sudo bash scripts/setup/install-maintenance.sh --dry-run
   sudo bash scripts/setup/install-maintenance.sh
   ```

   sudoers は文法検証後に内容を表示し、所有者が `yes` と入力したときだけ追加します。この導入で実際の復元やゲームの停止は行いません。

3. Raspberry Pi のリポジトリで Bot を更新して起動する。

   ```bash
   .venv/bin/pip install -e .
   sudo systemctl start gameserver-bot.service
   ```

4. `/server diagnose` と `/server backups` を確認する。復元の実機テストは、失って困らないテスト用ワールドとバックアップで行ってください。

## 復元の流れ

1. `/server restore` からバックアップを選択する。
2. 対象名・日時・「保存フォルダー全体が巻き戻る」ことを確認する。
3. 90秒以内に実行者本人が確認ボタンを押す。ここでロールとチャンネルも再確認する。キャンセル・期限切れでは復元しない。
4. サーバー側で、選択時からバックアップのファイル情報が変わっていないか再確認する。
5. 接続人数を確認してから、候補の専用コピーを展開・検証する。
6. 人数を再確認し、無人ならゲームを保存・停止する。
7. 現在のワールドを `valheim-pre-restore-日時-ID.tar.gz` に保存・検証する。これが失敗したら切り替えない。
8. 検証済みのワールドへ切り替え、ゲームを起動し、A2S 応答を確認する。

進行と直近の結果は `/server status` に表示し、通常の通知先にも完了結果を送ります。処理は独立した systemd ジョブなので SSH 切断や Bot 再起動で止まりません。最大実行時間は1時間です。

接続者あり・人数不明なら拒否します。確認と停止の間の新規接続を完全に排除するものではないので、利用者がいない時間に実行してください。復元中は既存の起動・停止・更新・バックアップなどもサーバー側で拒否し、自動停止の対象外にします。

## バックアップの意味と保護

- 対象はこのリポジトリが作る `valheim-world-...tar.gz` と復元前バックアップです。ゲーム独自の保存履歴や任意パスは選べません。
- 一覧表示は軽量なファイル情報の取得です。内容の検証は復元処理で行います。既存バックアップを無条件に「検証済み」とは表示しません。
- ファイル名はシェル引数へ埋め込まず、固定の SSH コマンド `restore` に小さな JSON データとして標準入力から渡します。
- 絶対パス、親ディレクトリへの移動、シンボリックリンク、ハードリンク、特殊ファイル、重複パス、破損・空のアーカイブを拒否します。
- `/etc/valheim/valheim.env` の `VALHEIM_WORLD` に対応する `.fwl` と `.db`（ファイルまたはデータディレクトリ）が必要です。設定と一致しないバックアップで新しいワールドが生成されることを防ぎます。設定ファイルの内容やパスワードは Discord に出しません。
- アーカイブの安全性・読み取り可能性を検証しますが、ゲーム独自のデータ内容の完全性までは保証しません。復元後はクライアントで進行を確認してください。ゲーム本体のバージョンは変更しません。
- 復元前アーカイブは通常のバックアップ世代整理では削除しません。切り替え前のディレクトリも `worlds_local` と同じ親ディレクトリの `.before-restore-ID` に残します。増えた分の容量は所有者が確認し、不要になったものを整理してください。

## 中断・失敗時

展開・事前バックアップまでの失敗では現行ワールドを切り替えません。ディレクトリ切り替えで失敗したら元の配置へ戻すことを試み、ゲームは自動起動しません。元へ戻せなかった場合や切り替え中に電源断した場合は `restore-block` が残り、Bot からの起動などを拒否します。

`/server diagnose` の「復元の手動確認」が必要になった場合、所有者が以下を確認してください。

```bash
sudo journalctl -u valheim-restore.service -n 100 --no-pager
sudo journalctl -u valheim-server.service -n 100 --no-pager
```

`restore-block` はワールドが空の状態で起動しないための保護です。`worlds_local`・`.before-restore-ID`・復元前バックアップの状態を確認し、正しいワールドを配置してから、所有者が保護を解除します。確認せずにマーカーだけを消さないでください。

起動確認だけが失敗した場合は、ゲームが起動途中または再起動中の可能性があります。自動で旧ワールドへ巻き戻すことはしません。`/server status` とログを確認してください。

停止段階の記録はこの機能の導入以後に蓄積されます。過去の履歴の復元や、SSH だけで物理的な電源断を確認する機能ではありません。
